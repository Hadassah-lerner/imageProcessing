# תרגיל 9 - המרה לגווני אפור

## 1. מה הבעיה בחישוב הממוצע?

הבעיה היא שהערוצים נקראים ב-OpenCV כ-`np.uint8`. הטווח שלהם הוא 0-255, וחיבור של ערכים כאלה עלול לבצע **overflow** לפני החלוקה ב-3.

לדוגמה, סכום אמיתי שגדול מ-255 אינו יכול להישמר נכון ב-`uint8`, ולכן הוא עלול "להיעטף" לערך אחר.

```python
gray = (img[:, :, 0] + img[:, :, 1] + img[:, :, 2]) / 3
```

לכן צריך לבצע את החישוב לאחר המרה לטיפוס שיכול להכיל ערכים גדולים יותר.

## 2. שתי דרכים לחישוב הממוצע

דרך ראשונה: ממירים את התמונה ל-`int32` ואז מחשבים `mean` לאורך `axis=2`.

דרך שנייה: ממירים ל-`float64` ומחשבים `sum` לאורך `axis=2`, ואז מחלקים ב-3.

```python
img_int = img.astype(np.int32)
gray_mean_1 = img_int.mean(axis=2)

gray_mean_2 = img.astype(np.float64).sum(axis=2) / 3
```

## 3. המרה לפי נוסחת המשקולות

מכיוון ש-OpenCV שומר את הערוצים בסדר B, G, R, המשקולות נכתבות בסדר הזה:

```python
weights = np.array([0.114, 0.587, 0.299])
```

Broadcasting מתאים את וקטור המשקולות בגודל 3 לכל פיקסל.

```python
weights = np.array([0.114, 0.587, 0.299])

gray = (img.astype(np.float64) * weights).sum(axis=2)
gray = np.clip(gray, 0, 255).astype(np.uint8)
```

## 4. השוואה ל-`cv2.cvtColor`

אין לבצע את החיסור ישירות בין שני מערכי `uint8`. בחיסור כזה תוצאה שלילית אינה יכולה להישמר כשלילית ב-`uint8` ועלולה להתעטף לערך גדול.

לכן לפני החיסור ממירים את שני המערכים לטיפוס רחב וחתום, למשל `int16`.

```python
difference = np.abs(
```

## 5. האם רואים הבדל?

בדרך כלל רואים הבדל קטן מאוד או כמעט לא רואים הבדל. הסיבה היא שהממוצע הפשוט נותן משקל שווה לשלושת הערוצים, ואילו נוסחת ההמרה נותנת משקל גדול יותר לירוק, משקל בינוני לאדום ומשקל קטן לכחול.

לכן הגוונים יכולים להיות מעט שונים, גם אם מבחינה חזותית ההבדל קטן.

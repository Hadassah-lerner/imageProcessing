# תרגיל 3 - גלישה מטווח הערכים (Overflow)

## חלק 1: טבלת תחזיות

המערך הנתון הוא `x = [100, 200, 250]`.

| expression | my guess | actual result |
|------------|----------|---------------|
| x + 10 | [110 210 4] | [110 210 4] |
| x + 100 | [200 44 94] | [200 44 94] |
| x - 150 | [206 50 100] | [206 50 100] |
| x * 2 | [200 144 244] | [200 144 244] |
| x.astype(np.int16) + 100 | [200 300 350] | [200 300 350] |
| x * 1.5 | [150. 300. 375.] | [150. 300. 375.] |
| (x * 1.5).dtype | float | float64 |

## חלק 2: מה קורה כשמבצעים `x + 300`?

הביטוי `x + 300` גורם לשגיאה מסוג `OverflowError`, מכיוון שלא ניתן לייצג את המספר 300 באמצעות הטיפוס `uint8`

## חלק 3: הפונקציה `add_safe`

הפונקציה ממירה תחילה את המערך לטיפוס `int16`, כדי שהחיבור יוכל להתבצע בלי גלישה בטווח של `uint8`.

לאחר מכן, `np.clip` מגבילה את התוצאות לטווח שבין 0 ל-255, ולבסוף `astype(np.uint8)` ממירה את התוצאה בחזרה לטיפוס `uint8`.

- `add_safe(x, 100)` מחזירה `[200 255 255]`. ערכים הגדולים מ-255 מוגבלים ל-255.

- `add_safe(x, -150)` מחזירה `[0 50 100]`. ערכים הקטנים מ-0 מוגבלים ל-0.

## חלק 4: מדוע `np.clip(x + 100, 0, 255)` אינו מספיק?

החיבור `x + 100` מתבצע לפני הפעלת `np.clip`.

מכיוון שהמערך הוא מסוג `uint8`, עלולה להתרחש גלישה כבר בשלב החיבור. לדוגמה, התוצאה המתמטית של `200 + 100` היא 300, אך בטיפוס `uint8` היא עשויה להפוך ל-44.

בשלב הזה, `np.clip` מקבלת את הערך 44 ואינה יכולה לדעת שהערך המקורי היה אמור להיות 300.

לכן, יש להמיר את המערך לטיפוס רחב יותר לפני החיבור, ורק לאחר מכן להגביל את התוצאה לטווח שבין 0 ל-255.

## חלק 5: תרגיל בונוס - `int8`

טווח הערכים של `int8` הוא בין ‎-128 ל-127.

כאשר מחברים 1 לערך 127 במערך מסוג `int8`, התוצאה עשויה לגלוש ולהפוך ל-‎-128.
